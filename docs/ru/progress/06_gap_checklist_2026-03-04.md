# Чеклист разрывов Шамалгана относительно рекомендаций MATSim (2026-03-04)

Чеклист сопоставляет текущее состояние Шамалгана с:
- MATSim Book Part One (`partOne-latest.pdf`, сборка 2025-06-15)
- `matsim-scenarios/matsim-berlin` (снимок main на 2026-03-04)

## Что уже согласовано

- Есть минимальная структура сценария:
  - `config` + `network` + `plans` позволяют запуск.
- Конвейер ОТ в двух вариантах:
  - конвертер из GTFS (`PrepareShamalganTransitFromGtfs`)
  - запасной вариант по допущениям (`PrepareShamalganTransitFromAssumptions`)
- Запуск с ОТ работоспособен и проверен как минимум до итерации 10.
- Маршрутизатор ОТ: `SwissRailRaptor`.
- Выходная диагностика и документация по преемственности уже на хорошем уровне.

## Разрывы (по приоритету)

### 1) Высокий: предложение ОТ по-прежнему в основном заглушка, а не проверенные операции

- В `docs/progress/03_pt.md` зафиксировано: базой служит supply на основе остановок OSM и допущений.
- В главе по ОТ MATSim ожидается реалистичное расписание, остановки и транспорт для осмысленного поведения ОТ.

Влияние:
- Пассажиропоток ОТ, пересадки и загрузка в салоне недостаточно надёжны для выводов по политике.

### 2) Высокий: Нет явного цикла калибровки по наблюдаемым подсчётам/долям режимов/расстояниям

- В проекте фиксируются выходы, но нет формального итеративного скрипта/процесса калибровки.
- И книга MATSim, и практика Berlin опираются на повторяющиеся циклы калибровки и измеримые цели.

Влияние:
- Удовлетворительная сходимость может не соответствовать реалистичному поведению.

### 3) Высокий: Реалистичность спроса ограничена (простая структура активностей и фиксированные начальные доли)

- Генератор населения использует `home/work/other`, фиксированную долю занятых и фиксированные начальные вероятности режимов.
- Для bootstrap приемлемо, но ниже типичной практики сценариев для продакшена.

Влияние:
- Эластичность по режиму/времени/цели ограничена; чувствительность сценария может быть смещённой.

### 4) Средний: Объекты (facilities) и богатая система активностей отсутствуют в активном пути запуска

- В активных конфигах не подгружается файл facilities.
- В сценариях в стиле Berlin используются facilities и более богатая типизация активностей для реалистичности выбора целей и скоринга.

Влияние:
- Реалистичность выбора целей и ограничений по активностям слабее, чем рекомендуется для зрелых сценариев.

### 5) Средний: Архитектура запуска ещё не в формате MATSimApplication

- `RunShamalgan` загружает конфиг напрямую и передаёт в `RunMatsim`.
- Berlin использует `MATSimApplication` для CLI-опций, масштабирования выборки, стандартизированной пред-/постобработки и удобных операций со сценарием.

Влияние:
- Сложнее масштабировать воспроизводимые варианты запуска (`--1pct/--3pct/...`) и режимы калибровки.

### 6) Средний: Проблема переносимости из-за абсолютных путей вывода в конфигах сценария

- В `scenarios/shamalgan/config.xml` используются относительные пути вывода (без абсолютных путей Windows).
- Рекомендации MATSim — относительные пути и переносимые конфиги.

Влияние:
- Воспроизводимость на разных машинах/ОС хрупкая.

### 7) Средний: Покрытие тестами пути запуска Шамалгана по сути отсутствует

- Существующий тестовый файл был закомментирован и ссылался на старый путь Gunma.
- В Berlin есть лёгкие тесты запуска сценария в CI для быстрой регрессии.

Влияние:
- Рефакторинг может незаметно сломать точку входа или допущения конфига.

### 8) Низкий: Стратегия упаковки данных может быть чище для долгосрочной совместной работы

- Репозиторий сейчас несёт тяжёлые артефакты и выходы для удобства миграции.
- Berlin держит большие входы/выходы снаружи и сохраняет репозиторий лёгким где возможно.

Влияние:
- Трение при клонировании/CI и раздувание репозитория со временем.

## Приоритизированный план внедрения

### Фаза 1 (сразу, 1–2 дня): Защита воспроизводимости

1. Заменить абсолютные пути вывода на относительные в обоих конфигах сценария.
2. Добавить один активный интеграционный тест для Шамалгана:
   - запуск 0–2 итераций на уменьшенной выборке;
   - проверка кода возврата и наличия основных выходных файлов.
3. Сохранить текущий конвейер ОТ по допущениям, но явно пометить в документации и комментариях как `bootstrap`.

Результат:
- переносимые конфиги и проходящий базовый тест запуска.

### Фаза 2 (коротко, 3–5 дней): Улучшение спроса и поведения

1. Расширить генерацию населения:
   - явный атрибут наличия автомобиля (car availability);
   - разбить внерабочие активности как минимум на образование/покупки/досуг.
2. Включить `considerCarAvailability=true` после заполнения атрибутов.
3. Добавить документированный вариант сценария для быстрых расчётов на малой выборке.

Результат:
- более реалистичный выбор режима и быстрее цикл калибровки.

### Фаза 3 (коротко, 3–7 дней): Обновление данных по ОТ

1. Приоритизировать загрузку GTFS или проверенных последовательностей остановок с окнами обслуживания и интервалами. Пока замораживаем этот пункт. Данных GTFS в ближайщее время не будет.
2. Перегенерировать:
   - `network-with-pt.xml`
   - `transitSchedule.xml`
   - `transitVehicles.xml`
3. Проверить согласованность расписания и привязку остановок к линкам до запуска.

Результат:
- первый расчёт с ОТ на основе данных вместо заглушек.

### Фаза 4 (средний срок, 1–2 недели): Процесс калибровки

1. Определить набор целей и допустимые диапазоны:
   - подсчёты (если есть),
   - доли режимов,
   - распределения по расстоянию/времени поездки,
   - время в пути по коридорам.
2. Сделать повторяемый скрипт калибровки:
   - запуск → извлечение КПЭ → оценка разрыва → применение следующего набора параметров.
3. Фиксировать каждый цикл калибровки в `docs/progress/04_runs.md`.

Результат:
- прозрачный и воспроизводимый процесс калибровки.

### Фаза 5 (средний срок, по желанию): Подтягивание архитектуры к стилю Berlin

1. Ввести класс запуска на базе `MATSimApplication` для Шамалгана.
2. Добавить опции выборки (`--1pct`, `--3pct` и т.д.) и стандартизированные хуки постобработки.
3. Оставить текущую точку входа `RunShamalgan` как обёртку совместимости на переходный период.

Результат:
- более чистая работа со сценарием и упрощённая поддержка.
