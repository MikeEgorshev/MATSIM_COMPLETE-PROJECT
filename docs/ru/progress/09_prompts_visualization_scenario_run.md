# Промпты для агента визуализации: запуск сценария и отчёт

Документ содержит готовые формулировки для передачи агенту по визуализации ([Agents/Agent_Visualization.md](../../Agents/Agent_Visualization.md)): (1) инфографика по результатам запуска сценария Шамалган, (2) отчёт по проделанной работе с визуализацией.

---

## Промпт 1: Инфографика по запуску сценария

**Кому:** Агент по визуализации.

**Контекст:** Мы запускаем сценарий Шамалган (MATSim): УДС `scenarios/shamalgan/network-with-pt.xml`, население `population.xml`, ОТ (transitSchedule, transitVehicles), конфиг `config.xml`. После прогона появляются выходы в `scenarios/shamalgan/output/` (или указанная в конфиге папка): события (events.xml.gz), планы (output_plans.xml.gz), возможно счётчики по звеньям и т.д.

**Задача:** Сделать понятную и наглядную инфографику по результатам этого запуска. Инфографика должна быть «хорошей и понятной»: с подписями, легендой, единым стилем и без лишнего шума.

**Что включить (по возможности, с учётом имеющихся данных и инструментов):**

1. **Загрузка сети (потоки по звеньям):** тепловая карта или категории загрузки (например, число проездов/час или объём по link id) по дорожной сети. Цель — сразу видеть, где сеть нагружена сильнее. Если в выходах есть агрегаты по звеньям (link volumes, counts) — использовать их; если нет — при необходимости предложить короткий скрипт извлечения из events и построения карты.
2. **ОТ — посадки/высадки:** если есть события с остановками (PersonEntersVehicle / PersonLeavesVehicle с stopId или маршрутом), сделать визуализацию: по маршрутам и/или по времени суток (например, столбчатая диаграмма или тепловая карта «маршрут × час»). Уже есть скрипт `tools/analyse_pt_boardings_from_events.py` — при необходимости использовать его выход (CSV) для графика.
3. **Сводка по сценарию:** один слайд или блок с ключевыми цифрами: число агентов, число итераций, общее число поездок (или по режимам car/pt/walk), при возможности — средняя длина поездки или доля ОТ. Источник: события и/или output_plans. Формат: статичная картинка (PNG) или лаконичная HTML-страница с текстом и мини-графиками.
4. **Единый стиль:** шрифты читаемые, легенды подписаны, цвета контрастные и различимые; при нескольких картинках — общая палитра и оформление (например, одна цветовая схема для загрузки сети).

**Ограничения:** Не менять входные данные сценария; использовать только выходы прогона и существующие входы (network, population, schedule). Сохранять артефакты в `analysis-artifacts/` или `Visualization/` с понятными именами (например `scenario_run_link_volumes.png`, `pt_boardings_by_route_hour.png`, `scenario_run_summary.png`). По возможности опираться на существующие скрипты (`tools/plot_network_*.py`, `tools/analyse_pt_boardings_from_events.py`, `tools/build_pt_map_html.py`) и пути из [Visualization/README.md](../../Visualization/README.md).

**Результат:** набор визуализаций (PNG/SVG/HTML), по которым можно быстро понять результат прогона: где загрузка сети, как ведёт себя ОТ, основные агрегаты. Кратко описать в README или в том же каталоге: что изображено, от какого прогона (путь к output), как воспроизвести (команда скрипта).

## Промпт 2: Отчёт по проделанной работе с визуализацией

**Кому:** Агент по визуализации.

**Контекст:** В проекте уже есть ряд визуализаций: карта маршрутов ОТ (pt_routes_map.html, pt_routes_map.svg), карта распределения населения по сети (population_on_network_map.html), визуализации зон (analysis-artifacts/zone-derivation/), обзоры полос и скоростей сети, инфографики по расписанию ОТ и т.д. Часть из них была создана или обновлена в рамках анализа УДС, ОТ и населения (см. [07_uds_pt_population_analysis.md](07_uds_pt_population_analysis.md)).

**Задача:** Написать **отчёт по проделанной работе с визуализацией** для сценария Шамалган.

**Содержание отчёта:**

1. **Цель и объём:** зачем нужна визуализация в проекте (проверка данных, отладка, презентация результатов анализа и прогонов).
2. **Перечень визуализаций:** таблица или список с указанием для каждой визуализации:
   - название и тип (карта сети, карта ОТ, карта населения, график, инфографика и т.д.);
   - путь к файлу (например `Visualization/pt_routes_map.html`, `analysis-artifacts/zone-derivation/04_density_roads_zones_new_map.png`);
   - источник данных (какие файлы сценария или артефактов использованы);
   - как воспроизвести (команда скрипта из `tools/` или описание ручных шагов);
   - краткое назначение (что показывает, для кого).
3. **Используемые инструменты:** какие скрипты и технологии используются (Python, matplotlib, Leaflet, и т.д.), где они лежат, какие форматы вывода (SVG, PNG, HTML).
4. **Ограничения и рекомендации:** что пока не визуализировано или визуализировано упрощённо; рекомендации по обновлению при изменении сети/расписания/населения (например, перезапуск скрипта после пересборки network или transitSchedule).
5. **Связанные документы:** ссылки на [Visualization/README.md](../../Visualization/README.md), [Agent_Visualization.md](../../Agents/Agent_Visualization.md), отчёт анализа УДС/ОТ/населения [07_uds_pt_population_analysis.md](07_uds_pt_population_analysis.md).

**Формат:** один документ в Markdown, разместить в `docs/ru/progress/` (например `10_visualization_work_report.md`). При необходимости добавить англоязычную версию в `docs/en/progress/`. Язык — русский (или EN для en-версии); стиль — краткий и по делу, для разработчиков и заказчиков проекта.

**Результат:** готовый отчёт, по которому можно понять, какие визуализации есть, откуда они берутся и как их обновить после изменений данных или нового прогона сценария.
