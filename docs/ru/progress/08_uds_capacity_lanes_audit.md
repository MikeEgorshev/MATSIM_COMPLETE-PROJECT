# Проверка атрибутов УДС: пропускная способность и полосность

## 1. Откуда берутся значения в сценарии Шамалган

### Источник сети
- **Вход:** OSM (`original-input-data/shamalgan/map`) — парсится как XML, используется **OsmNetworkReader** (не SupersonicOsmNetworkReader).
- **Постобработка:** `PrepareShamalganNetwork`: (1) перезапись полосности из тегов OSM `lanes`, `lanes:forward`, `lanes:backward`; (2) опционально профиль `poor` — снижение скорости и пропускной способности.

### Пропускная способность (capacity)

Исходные значения задаются **дефолтами MATSim OsmNetworkReader** — это **пропускная способность на одну полосу** (авт/ч), затем умножается на число полос линка. Ниже — значения **на полосу** из исходного кода MATSim (org.matsim.core.utils.io.OsmNetworkReader):

| OSM highway       | Полос по умолчанию (на направление) | Capacity на полосу (авт/ч) |
|-------------------|--------------------------------------|----------------------------|
| motorway          | 2                                    | 2000                       |
| motorway_link     | 1                                    | 1500                       |
| trunk             | 1                                    | 2000                       |
| trunk_link        | 1                                    | 1500                       |
| primary           | 1                                    | 1500*                      |
| primary_link      | 1                                    | 1500*                      |
| secondary         | 1                                    | 1000                       |
| secondary_link    | 1                                    | 1000                       |
| tertiary          | 1                                    | 600                        |
| tertiary_link     | 1                                    | 600                        |
| unclassified      | 1                                    | 600                        |
| residential       | 1                                    | 600                        |
| living_street     | 1                                    | 300                        |
| service           | (как в OSM/дефолт)                   | (из того же набора типов)  |

\* При включённом `useVspAdjustments` у primary/primary_link стоит 1000, в стандартной конфигурации — 1500.

Итоговая **capacity линка** = число полос (направления) × capacity на полосу. Поэтому в сети получается диапазон **300–4000 авт/ч** (1 полоса × 300 и 2 полосы × 2000).

В проекте полосность затем **переопределяется** из OSM:
- `PrepareShamalganNetwork.defaultPerDirectionLanes`: motorway/trunk → 2 полосы на направление, остальные классы → 1 полоса; при наличии тега `lanes` / `lanes:forward` / `lanes:backward` берётся значение из OSM.
- Профиль **poor**: capacity умножается на 0,70–0,85 (в зависимости от класса скорости), нижняя граница 150 авт/ч.

## 2. Нормативное сравнение

### 2.1 Пропускная способность полосы

**HCM (Highway Capacity Manual):**
- Автомагистрали (uninterrupted flow): базовая пропускная способность порядка **2300 легк. авт/ч на полосу** (65 mph, идеальные условия); итоговая с учётом PHF, тяжёлых ТС и т.д. обычно ниже.
- Сельские двухполосные дороги: порядка **3200 авт/ч суммарно на оба направления** в идеальных условиях.
- Городские улицы со светофорами: насыщающий поток **~1460–1566 авт/ч на полосу** (измерения, напр. District of Columbia).
- Городские магистрали (midblock, без перекрёстков): порядка **1482–2105 PCU/ч на полосу** в зависимости от скорости и условий.

**РФ (МГСН, методики):**
- Пересечения **в одном уровне** (регулируемые перекрёстки): **750–850 приведённых авт/ч на полосу** (без левоповоротных потоков).
- Пересечения **в разных уровнях**: **1200–1550 приведённых авт/ч на полосу**.
- Многополосные дороги (ОДМ 218.2.020-2012): **2100–2200** (4 полосы) и **2200–2300** (6 полос) легк. авт/ч на полосу.

В MATSim capacity линка моделирует **непрерывный поток на перегоне** (без явной модели светофоров на узлах). Поэтому логично сопоставлять:
- **Магистрали / trunk / motorway** — с нормативами для участков в разных уровнях или многополосных дорог: 1200–2300 авт/ч на полосу. Значения MATSim **1500–2000 на полосу** попадают в этот диапазон.
- **Primary / secondary (городские магистрали)** — в реальности часто ограничены перекрёстками (750–850 на полосу в РФ на перекрёстке; 1482–2105 на перегоне). MATSim даёт **1000–1500 на полосу** — ближе к перегону, для узлов без светофорной модели это может быть завышено.
- **Tertiary / residential / unclassified** — 600 авт/ч на полосу в MATSim консервативнее или сопоставимо с 750–850 на перекрёстке; для жилых и второстепенных улиц это разумно.
- **living_street** — 300 авт/ч на полосу соответствует зоне с сильным смешением потоков и пешеходами.

### 2.2 Полосность

- Дефолты MATSim: **1 полоса на направление** для primary, secondary, tertiary, residential и т.д., **2 полосы** для motorway/trunk — соответствуют типичной иерархии УДС.
- В проекте полосность **перезаписывается из OSM** (`lanes`, `lanes:forward`, `lanes:backward`) с теми же дефолтами при отсутствии тегов — логика корректна; итоговая полосность 1 или 2 по документированным параметрам сети (2 991 линк, 1 128 узлов) согласуется с малой агломерацией/районом.

## 3. Выводы

| Атрибут | Оценка | Комментарий |
|--------|--------|-------------|
| **Capacity на полосу (motorway/trunk)** | OK | 1500–2000 в пределах 1200–2300 по HCM/РФ для непрерывного потока. |
| **Capacity на полосу (primary/secondary)** | Приемлемо с оговоркой | 1000–1500 — разумно для перегона; для городских узлов без светофоров может быть оптимистично (нормы РФ 750–850 на перекрёстке). Для сценария без явной модели светофоров допустимо. |
| **Capacity на полосу (tertiary/residential/unclassified)** | OK | 600 — консервативно или в норме относительно 750–850. |
| **Capacity living_street** | OK | 300 — уместно для жилых зон. |
| **Полосность** | OK | Дефолты 1/2 и переопределение из OSM соответствуют иерархии УДС; диапазон 1–2 полосы на направление реалистичен. |
| **Профиль poor** | OK | Снижение capacity на 15–30% и floor 150 авт/ч согласуется с ухудшенными условиями. |

**Рекомендации:**
1. Оставить текущую логику capacity и полосности без обязательных изменений для текущих целей сценария (тест интеграции ОТ, загрузка, распределение населения).
2. При последующей калибровке по подсчётам или при вводе светофорной модели — рассмотреть снижение capacity для primary/secondary в городских условиях (например, к 800–1000 на полосу для линков, примыкающих к перекрёсткам в одном уровне), с опорой на МГСН/ОДМ и местные обследования.
3. Явно зафиксировать в документации сценария: capacity в MATSim трактуется как пропускная способность **перегона** (uninterrupted), а не перекрёстка; полосность и класс дороги задаются из OSM с дефолтами MATSim.
