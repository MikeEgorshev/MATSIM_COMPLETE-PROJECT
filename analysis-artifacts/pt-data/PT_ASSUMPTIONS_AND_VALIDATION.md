# Допущения модели ОТ и план валидации (Шамалган)

Документ фиксирует допущения mockup-модели общественного транспорта и результаты проверки конфигурации на принудительную долю ОТ. Используется для оценки реалистичности и последующей калибровки.

---

## 1. Проверка конфигурации: доля ОТ не задана принудительно

**Проверены файлы:** `scenarios/shamalgan/config.xml`.

**Результат:** В сценарии **нет параметров, задающих конкретную целевую долю ОТ**. Доля поездок на ОТ формируется в результате:

- **Scoring (полезность режимов):**
  - `car`: constant = 0.0, marginalUtilityOfTraveling_util_hr = 0.0, monetaryDistanceRate = -0.00025
  - `pt`: constant = -0.8, marginalUtilityOfTraveling_util_hr = 0.0
  - `walk`: constant = -1.4, marginalUtilityOfTraveling_util_hr = 0.0

- **Выбор режима:** включён `SubtourModeChoice` (weight 0.1) с режимами `car,pt,walk`, `probaForRandomSingleTripMode = 0.5`. Режимы не зафиксированы в планах — агенты могут переключаться между итерациями.

- **Транзит:** `additionalTransferTime = 120` с, что влияет на привлекательность поездок с пересадками, но не задаёт долю ОТ напрямую.

Итог: конфигурация допускает эндогенное формирование доли ОТ; для калибровки под наблюдаемую долю следует корректировать константы полезности и при необходимости `additionalTransferTime`.

## 2. Таблица допущений модели ОТ (mockup)

| Параметр | Значение | Источник / примечание |
|----------|----------|------------------------|
| **Время стоянки (dwell)** | 60 с на всех остановках | Константа в `PrepareShamalganTransitFromAssumptions`; при использовании tagged CSV можно задать per-stop (см. опцию dwell CSV). |
| **Скорость ОТ** | 30 км/ч (по умолчанию) | Аргумент командной строки или `DEFAULT_SPEED_KMH`; при использовании профиля — по маршруту из `pt_service_profile.csv` (колонка `speed_kmh`). |
| **Вместимость автобус** | 35 мест + 30 стоячих | `pt_service_profile.csv` / константы bus_std. |

| **Интервалы (headway)** | По периодам из `pt_service_profile.csv` | Периоды 06–07, 07–10, 10–16, 16–20, 20–23; для маршрутов 6, 11, 213 — калибровка среднего интервала под целевые значения (см. `ROUTE_YANDEX_TARGET_AVG_HEADWAY_SEC`). |
| **Окно обслуживания** | 06:00–23:00 | По умолчанию в коде и в профиле. |
| **Геометрия маршрутов** | 4 маршрута (6, 11, 213, 256) | `tagged_route_stops.csv` из `new_map.gpkg`; трасса по дорожной сети (Dijkstra), для 213 — обязательный коридор, для 256 — ограничение по origid. |
| **Расположение остановок** | Snap к ближайшему link | Одна точка на остановку; обратное направление — обратный link при наличии. |

Целевые средние интервалы по маршрутам (калибровка при наличии профиля): маршрут 6 — 30 мин, 11 — 15 мин, 213 — 10 мин (см. константы в коде).

## 3. План валидации пассажиропотока

1. **Анализ после прогона**
   - Сбор посадок/высадок по маршруту и временному интервалу из событий симуляции (скрипт `tools/analyse_pt_boardings_from_events.py`). Выход: `pt_boardings_alightings_by_route_hour.csv` (и при наличии событий с stopId — по остановкам).
   - Сравнение с наблюдениями/APC (если появятся): объём по остановкам/линиям, выявление переполнений (boarding > вместимость рейса).

2. **Калибровка**
   - При появлении данных по пассажиропотоку: сравнение симулированных и наблюдаемых объёмов; корректировка headway, времени стоянки и модальных коэффициентов (Фаза 3–4 плана интеграции реального ОТ).
